# Repository code and security review

Reviewed on 5 October 2026. Baseline: `87373be` (`ci: support automatic docker tagging for git tags`).

**Assessment: resolve the high-priority findings before exposing this service to an untrusted network or using it to render untrusted sites.** The main problems are demonstrable SSRF bypasses, ineffective resource limits, permissive authentication startup, and releases without enforced validation. The repository also advertises functionality that is absent and has a failing test suite.

This is a review and remediation draft; application code, configuration, dependencies, and existing user files were not changed.

## Scope and threat model

Read all 13 Python source modules, all committed tests, benchmark code and scorecard, package metadata and lockfile, Dockerfile, startup script, GitHub/GitLab pipelines, pre-commit settings, ignore files, and README. Inspected the six untracked experimental Python scripts and the existing untracked Trivy report separately from committed code. Checked 76 historical Git blobs for selected known secret formats. No repository-specific `AGENTS.md` was found in the repository or ancestor directories.

The service receives arbitrary URLs and search queries from an MCP client and processes attacker-controlled HTML, scripts, DNS answers, redirects, and model responses. Assets include the host/container network, local services, memory/CPU, LLM credentials and spend, and the integrity of extracted data and reports. Authentication reduces who can invoke tools; it does not make fetched websites trustworthy. Single-user operation does not remove these risks.

Validation used the existing Python 3.13.14 environment. Key installed package versions match the lockfile: FastMCP 3.4.2, MCP 1.28.1, HTTPX 0.28.1, and Playwright 1.60.0. The Playwright-matched Chromium revision was missing locally; browser probes used the already cached Chromium headless shell revision 1234. Thus browser results are real integration observations with that cached browser, supported by upstream routing documentation, rather than validation of the exact Docker browser build.

No public targets were attacked. SSRF probes used an ephemeral loopback HTTP fixture and fake DNS answers/origin mapping. The complete current Docker image was not built or scanned, no live LLM/provider requests were made, and exploitability of upstream dependency advisories was not exhaustively tested. Secret scanning was a selected-pattern scan, not a substitute for Gitleaks or an assurance that no secrets exist.

### F01 — Browser routing bypasses

Location: [browser.py:57](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:57), [browser.py:75](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:75), [fetch.py:122](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:122).

The route guard validates a URL and calls `route.continue_()`, allowing Chromium to follow redirects without another guard invocation. A controlled initial origin returned a redirect to loopback: the guard recorded only the initial URL, while Chromium loaded the private response. Separately, a page opened `ws://127.0.0.1:<fixture-port>/ws`; the local fixture received the handshake and the guard never saw that URL. These bypasses occur with `allow_private_networks=False` and are reachable through explicit rendering or automatic static-to-browser fallback.

The current context also allows service workers, which have documented routing limitations. This was not separately exploited. Playwright documents [redirect routing behavior](https://playwright.dev/python/docs/api/class-page#page-route), [WebSocket routing](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route-web-socket), and [service-worker interception limits](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route).

**Fix:** enforce destination policy at the actual browser network connection using a guarded egress proxy/network boundary; cover redirects and all browser protocols. Explicitly disable unsupported WebSockets and service workers until guarded. Checking the final page URL after navigation is too late to prevent an internal request.

### F02 — DNS rebinding

Location: [security.py:68](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/security.py:68), [fetch.py:109](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:109), [browser.py:62](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:62).

`validate_url()` resolves a hostname but returns only the original URL. HTTPX and Chromium then resolve that hostname independently. The local probe returned `1.1.1.1` for validation and `127.0.0.1` for HTTPX connection establishment; the private fixture body was returned. Revalidating each redirect URL in the static path does not close this race.

**Fix:** bind each request's connection to a validated address, retaining the original HTTP authority, TLS SNI and certificate verification. Use an egress proxy for browser traffic and prohibit bypass. Handle mixed DNS answers, IPv6, retries, proxy environment variables, and redirects consistently.

### F03 — Non-global shared IPv4 addresses are allowed

Location: [security.py:25](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/security.py:25).

The predicate checks several special IP flags but does not require global routability. Python marks `100.64.0.0/10` as neither private nor globally routable. `validate_url('http://100.64.0.1/')` and `validate_url('http://100.100.100.200/')` both succeeded. Deployments using that range for internal services remain reachable through the scraper.

**Fix:** deny non-global addresses, with explicit administrator-controlled exceptions where required. Add tests for shared, mapped IPv6, special-use and mixed-answer ranges on every supported Python version.

### F04 — Response-size and timeout limits are ineffective as hard bounds

Location: [fetch.py:83](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:83), [fetch.py:110](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:110), [fetch.py:126](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:126).

HTTPX `get()` downloads the complete response before slicing `resp.text`. The setting says bytes but slices Unicode characters. The bounded stream probe consumed 256 KiB despite a 16-byte cap and returned 32 UTF-8 bytes. robots.txt has no size cap at all. Browser content is truncated only after the browser has loaded resources and `page.content()` has allocated the full DOM serialization. Slow streams may continue beyond the configured HTTPX timeout because it limits individual I/O waits rather than total operation duration.

**Fix:** stream with explicit wire/decompressed/output limits and abort oversized bodies; bound robots responses, subresources and DOM work; enforce an end-to-end deadline covering DNS, redirects, rate waits, rendering and parsing. Retain process/container memory and CPU limits as a second boundary.

### F05 — HTTP authentication fails open

Location: [server.py:35](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/server.py:35), [Dockerfile:30](/home/enzo/Epita/labo/web-scraper/Dockerfile:30).

A missing or empty token only logs a warning; the MCP HTTP endpoint is still served without auth, including when the Docker image binds `0.0.0.0`. An in-memory initialize request with no credentials returned 200 when no token was configured. Configured auth correctly rejected a wrong token with 401, so the problem is startup policy, not a demonstrated bypass of valid token verification.

**Fix:** refuse HTTP startup without a valid token by default, and keep token-free stdio supported. If unauthenticated local HTTP is needed, require an explicit opt-in restricted to loopback. Document TLS termination for remote deployments and test empty-token behavior.

### F08 — Releases bypass validation and branch builds replace `latest`

Location: [docker-publish.yml:43](/home/enzo/Epita/labo/web-scraper/.github/workflows/docker-publish.yml:43), [security-scan.yml:28](/home/enzo/Epita/labo/web-scraper/.github/workflows/security-scan.yml:28), [.gitlab-ci.yml:57](/home/enzo/Epita/labo/web-scraper/.gitlab-ci.yml:57), [.gitlab-ci.yml:73](/home/enzo/Epita/labo/web-scraper/.gitlab-ci.yml:73).

GitHub publication runs independently of security scanning and has no lint/type/test jobs or dependency on their success. Trivy uses `exit-code: '0'`, so findings cannot fail that workflow. ### F09 — Unbounded work, inputs and retained state

Location: [browser.py:41](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:41), [browser.py:96](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:96), [fetch.py:37](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:37), [fetch.py:61](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:61), [research.py:98](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/research.py:98), [config.py:23](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/config.py:23).

The semaphore limits only short-lived browser contexts, not static requests, parsing, concurrent MCP calls or model requests. `new_session()` bypasses it if interaction is restored. Each research call starts concurrent source fetches, and multiple calls multiply work. Domain/robots caches and locks never expire or evict. Queries, prompts and schemas have no size bounds; the 100k extraction character budget does not bound schema/prompt size or total token use. Ollama generation has no output-token budget, and research can send 120k source characters at 15 sources despite README wording about 16k. Numeric settings accept zero/negative values; a zero page semaphore can stall all rendered calls.

**Fix:** validated positive settings, global/per-client admission limits, bounded queues and LLM concurrency, token/output budgets, input-size limits, TTL/LRU caches and job/session limits. A transport/proxy request-body cap should reject oversized inputs before expensive parsing.

### F10 — Blocking operations in async paths

Location: [fetch.py:148](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:148), [security.py:68](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/security.py:68), [fetch.py:142](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:142), [scrape.py:40](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/scrape.py:40).

Static validation executes synchronous `socket.getaddrinfo()` on the event loop, including redirect/robots checks. DNS delays can block unrelated MCP requests outside the HTTP timeout. HTML parsing and repeated extraction also run synchronously in that loop. The browser route path offloads DNS, but the shared fetch path does not.

**Fix:** bounded asynchronous resolution tied to connection policy, and bounded worker execution for expensive parsing. Validate with a slow resolver fixture and an unrelated request that must remain responsive.

### F11 — Chromium sandbox disabled in every environment

Location: [browser.py:50](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:50).

`--no-sandbox` is unconditional, including the documented host-based `uv run` launch. A non-root Docker user does not replace Chromium's renderer sandbox. This removes a defense against malicious websites if a browser vulnerability is encountered; no browser memory-corruption exploit was attempted.

**Fix:** launch with Chromium sandbox enabled and verify it in the supported runtime. Where kernel/container constraints prevent that, isolate rendering in a dedicated restricted worker with minimal filesystem/network access and document the actual boundary. Playwright's sandbox launch option must be set deliberately; merely removing the argument may leave its default disabled.

### F12 — robots.txt and per-origin policy drift

Location: [config.py:34](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/config.py:34), [fetch.py:83](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:83), [fetch.py:149](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:149).

Code defaults `respect_robots=False`; README says true. The sample `.env` only changes behavior when explicitly copied. When enabled, robots and the rate limiter apply to the original URL, not a redirect's destination. All non-200 robot responses, including 403 and redirects, are treated as permission, and cached rules never expire. Direct browser interaction would also require its own policy if restored.

**Fix:** align defaults with the advertised behavior; define HTTP status/error policy; follow validated bounded robot redirects; reapply policy on destination changes; expire caches. Distinguish crawl politeness from the SSRF boundary.

### F13 — Schema compliance is assumed

Location: [extract.py:49](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/extract.py:49), [extract.py:96](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/extract.py:96).

Both model paths return model-supplied arguments/JSON without local schema validation. Ollama accepts the first tool call without checking its function name or argument type. A mocked response containing a string price passed through successfully against a numeric schema. Valid JSON alone does not ensure required fields, types or constraints. Provider truncation/stop reasons are not checked either.

**Fix:** validate the caller schema, require the intended tool name and an appropriate argument object, validate returned data with JSON Schema, and return an explicit failure for invalid or truncated output. Any repair retry must have a fixed budget.

### F14 — Fetch status and browser readiness are not honored

Location: [fetch.py:156](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:156), [fetch.py:123](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/fetch.py:123), [extract.py:135](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/extract.py:135), [research.py:24](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/tools/research.py:24).

Fetch preserves non-success statuses but extraction/research ignore them, so error/challenge pages can be synthesized and cited as source facts. A short 404 triggers browser fallback while a large challenge page may avoid it. `domcontentloaded` followed immediately by `page.content()` does not ensure that asynchronous JS content has rendered. The load wait only runs if serialization throws; valid empty DOMs do not trigger it.

**Fix:** define accepted status/content types and explicit blocked/error states, avoid fallback for ordinary HTTP errors, and use a bounded content-readiness condition for JS pages. Return per-source diagnostics and validate citation indices rather than silently treating errors as evidence.

### F15 — Supply-chain claims exceed implementation

Location: [README.md:141](/home/enzo/Epita/labo/web-scraper/README.md:141), [docker-publish.yml:54](/home/enzo/Epita/labo/web-scraper/.github/workflows/docker-publish.yml:54), [.gitlab-ci.yml:80](/home/enzo/Epita/labo/web-scraper/.gitlab-ci.yml:80).

### F16 — Browser lifecycle gaps

Location: [browser.py:75](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:75), [browser.py:89](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:89), [browser.py:96](/home/enzo/Epita/labo/web-scraper/src/web_scraper_mcp/browser.py:96).

### F17 — Logs and launcher behavior

## Additional design concerns

- Page text is inserted next to instructions in extraction/research prompts. There is no explicit untrusted-source boundary or instruction to disregard commands inside sources. This can poison model output/citations; a live-model exploit was not tested. These internal model calls do not execute arbitrary tools, so this alone does not establish command execution or credential exfiltration. Add adversarial content fixtures, structured source delimiting and downstream validation, while acknowledging that prompting is not a security boundary.
- Model/provider selection is inferred from a `claude-` prefix; defaults choose Ollama even though parts of README say Anthropic is required. Model context budgets should be configurable and token-based; a fixed 32k window may still truncate a 100k-character input depending on language/model plus schema overhead.
- `Settings.ollama_url()` appends a port by checking for any colon in `netloc`. A bare bracketed IPv6 host therefore does not receive the default port, and a host with a path can have `:11434` appended to its path. Parse/normalize URL components explicitly and test documented configurations.
- The HTML fallback returns plain body text as “markdown” and can reintroduce boilerplate. Same-domain link comparison uses raw `netloc`, so casing/default ports/userinfo can affect grouping. Define canonical URL/domain semantics if map/crawl is restored.
- Settings and pools are import-time globals; typed backend protocols and injectable clients/settings would simplify deterministic tests. Anthropic clients are created per call without explicit context-managed closure. Keep refactoring subordinate to fixes, with tests for connection cleanup.

## Existing strengths

The static fetch path disables automatic redirects and validates each hop, blocks many common internal literals, verifies TLS by default, and caps redirect count. Configured bearer authentication rejects incorrect tokens. Browser contexts are short-lived on the normal successful path and have a concurrency semaphore. The image runs under a non-root user, `.env` is excluded from Git and Docker context, and builds use a frozen hashed lockfile.
